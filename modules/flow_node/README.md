# flow_node (узел полива)

Периферийный узел системы полива Smart Garden. Работает на **ESP8266**.
Отвечает за физическое открытие/закрытие клапанов по командам с Хаба.

Общее описание проекта и его философии — в
[`../../README.md`](../../README.md) (технический паспорт). Протокол
обмена — в [`../../PROTOCOL.md`](../../PROTOCOL.md). Этот файл — про то,
что конкретно делает `flow_node.ino`.

## Назначение

- Управляет до 4 клапанов полива.
- Периодически отправляет Хабу свой "паспорт" (`MSG_CONFIG`) и текущую
  телеметрию (`MSG_TELEMETRY`).
- Принимает от Хаба команды (`MSG_COMMAND`) на открытие/закрытие
  клапанов.
- Автоматически закрывает клапан при потере связи с Хабом дольше
  30 секунд (watchdog) — защита от "забытого открытым" клапана.

## Зависимости

- `<ESP8266WiFi.h>`, `<espnow.h>` — стандартный ESP8266 API.
- `<GardenProtocol.h>` + `<GardenNode.h>` из `../../libraries/GardenNet/`
  — вся протокольная логика (адресация, дедупликация, джиттер,
  watchdog-таймер, авто-ACK) реализована в библиотеке. `flow_node.ino`
  содержит только специфику полива: пины, что класть в payload, что
  делать с принятой командой. Подробный порядок использования
  библиотеки — `../../libraries/GardenNet/README.md`.

## Физическое подключение

На месте реального МОСФЕТ-ключа, управляющего клапаном, сейчас
светодиоды через резистор (для отладки протокола без реального
железа):

| Индекс клапана | GPIO | Маркировка NodeMCU/Wemos D1 mini |
|---|---|---|
| 1 | GPIO5 | D1 |
| 2 | GPIO4 | D2 |
| 3 | GPIO14 | D5 |
| 4 | GPIO12 | D6 |

Задаются массивом `valvePins[]` в начале файла — при другой распиновке
менять только его. Специально не задействованы загрузочные пины
ESP8266 (GPIO0/2/15/16), влияющие на режим старта платы. Подробнее —
`PROTOCOL.md` §6.1.

## Как это работает

1. При старте: настраивает пины (все клапаны сразу выключены), поднимает
   Wi-Fi/ESP-NOW, инициализирует `GardenNode` и сразу шлёт `MSG_CONFIG`
   — это же служит объявлением "я включился" для Хаба.
2. В фоне (`node.loop()`): раз в ~10 сек шлёт телеметрию, раз в ~1 час
   — конфиг (с джиттером, чтобы не сталкиваться в эфире с другими
   узлами при одновременном включении).
3. При получении команды (`onCommand`): реально переключает GPIO
   (`applyValveState`), включает watchdog, если клапан теперь открыт.
4. Если связи с Хабом нет дольше 30 сек, а клапан считается открытым —
   `onWatchdogTimeout` закрывает его самостоятельно, без команды.

## Известные ограничения текущей реализации

Подробный и актуальный список — `PROTOCOL.md` §7. Из специфичного для
этого модуля:

- **`mode=1` (полив по объёму) не реализован** — нет датчика потока и
  логики "лить, пока не наберётся N литров". Клапан реально открывается
  (через GPIO), но без ограничения по объёму.
- **Нет таймера на `duration_sec`** — команда держит клапан открытым до
  следующей команды или срабатывания watchdog, а не автоматически
  закрывает его через N секунд.
- **`current_flow`/`total_water_used` — заглушки**, всегда `0`. Не
  персистентны между перезагрузками (потребуется EEPROM/flash).
- **МОСФЕТ пока не подключён** — на пинах светодиоды, реальное
  управление клапаном ещё предстоит.
