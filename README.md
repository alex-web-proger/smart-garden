# Технический паспорт проекта «Smart Garden»

## 1. Назначение проекта

Автоматизированная распределённая система управления загородным участком (60×30 м).

- **Основная цель:** точный капельный полив грядок на основе агрономических циклов и климатических данных.
- **Вторичные цели (перспектива):** управление освещением, мониторинг пасеки (ульев), контроль запасов воды в башне.
- **Философия:** полная автономность. Система должна работать по локальному расписанию даже при полном отсутствии интернета или падении внешнего сервера.

## 2. Структура сети (топология)

Система строится по 3-уровневой схеме с возможностью расширения через ретрансляторы:

| Уровень | Описание |
|---|---|
| **Периферийные модули (МП)** | Конечные узлы на базе ESP8266 (ESP-12E). Управляют клапанами (до 4 шт.) и считывают датчик расхода воды. Питание — 12В (АКБ + солнечная панель). |
| **Центральный узел (Хаб/ЦПУ)** | Мощный контроллер на базе ESP32. Находится в доме. Является мостом между полем (ESP-NOW) и интернетом (Wi-Fi/MQTT). Имеет дисплей для локального управления. |
| **Ретрансляторы («Репки»)** | Промежуточные модули (ESP8266) для покрытия слепых зон. Не имеют своей логики, просто «пробрасывают» сигнал дальше. |
| **Внешний сервер** | Приложение на Laravel (PHP) для ведения истории севооборота, аналитики и связи с прогнозом погоды. |

## 3. Протокол обмена (прикладной уровень)

Связь между узлами осуществляется через **ESP-NOW** в режиме Broadcast (вещание на адрес `FF:FF:FF:FF:FF:FF`).

**Ключевые механизмы протокола:**

- **Идентификация** — по физическому MAC-адресу отправителя (зашит внутри пакета для прохождения через ретрансляторы).
- **Адресация** — поле `receiver_mac`. Устройства обрабатывают пакет, только если там их адрес или «нулевой» адрес (для Хаба).
- **Защита от дублей** — поле `packet_id` (счётчик 0–65535). Позволяет Хабу и периферии игнорировать повторные пакеты от ретрансляторов.
- **Борьба с эхом** — поле `hop_count`. Ретранслятор пересылает только пакеты с `hop_count == 0` (оригиналы), меняя его на 1. Это предотвращает зацикливание эфира.

## 4. Структура пакета данных (Universal Packet)

Для гибкости используется `union` (объединение памяти), разделённое на три логические части:

1. **Заголовок** — MAC-адреса, ID пакета, Hop Count, тип устройства, тип сообщения.
2. **`MSG_CONFIG` (Паспорт)** — передаётся редко. Содержит возможности железки (кол-во клапанов, наличие датчиков).
3. **`MSG_TELEMETRY` (Данные)** — передаётся часто. Текущие показатели (литры, активный клапан, расход).
4. **`MSG_COMMAND` (Команды)** — команды от Хаба к модулям (открыть клапан №X, выдать Y литров).

## 5. Особенности реализации

- **Масштабируемость** — новые модули добавляются в сеть без перепрошивки Хаба (Plug & Play по MAC-адресу).
- **Живучесть** — модули полива имеют физические тумблеры и краны для ручного управления. В коде МП предусмотрен Watchdog — автозакрытие клапанов при потере связи.
- **Экономия** — применение `union` позволяет держать размер пакета минимальным (около 20–30 байт), что критично для стабильности радиосвязи на больших расстояниях.
